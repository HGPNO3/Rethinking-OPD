# 01 参数配置审查（不含方法代码）

这份提交回答：上游怎么设，我们以前怎么设，哪些能沿用、哪些仍需确认。
集中看 [parameters.review.json](parameters.review.json)。它是审核表，不是训练入口读取的配置；null 表示迁入 OPD 后尚未确定，不表示自动继承或设为零。此次没有修改已运行实验的参数。

| 参数 | 固定上游 | 原 BudgetSI Qwen3 设置 | 本次处理 |
|---|---|---|---|
| 学习率 | 1e-6 | 1e-5 | 待审核；没有把原值直接搬成新默认 |
| weight decay | 0.01 | 0 | 待审核；两者会改变优化器更新 |
| LoRA rank / alpha | 0 / 16（未启用） | 32 / 64 | 待迁移验证；原3.5家族还有限定文本骨干的要求 |
| 生成温度 | 1.0 | 0.7 | 保留既有0.7协议要求，不代表OPD已接通；训练概率的1.0另由方法适配实现 |
| batch | 配置64 prompts，n=4 | 每次采集16段对话 | 单位不同；实际训练批为入选行动数B，不能直接64→16 |
| 长度 | prompt 1024 / response 7168 | 服务context 40960 | 不是同一含义；任务上限待确认 |

原参数来源是此前公开的 a984268 提交中 budgetsi/configs/qwen3.json；固定上游路径在JSON中逐项标明。上游值来自代码，不是从论文表格猜测；主脚本和Hydra继承都可能影响实际值。

审核时逐项问：这个差异由任务或资源需求解释吗？如果没有依据，应先采用上游设置建立基线还是安排对照？结论需要写明，不能把“原来就这样”当作证明。这里不新增已批准科学设置，也不启动实验。
